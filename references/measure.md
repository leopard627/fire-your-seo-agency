# 측정 루프 — 고치고 끝이 아니다

대행 서비스와 이 스킬의 진짜 차이는 여기다. 대행은 "작업했습니다" 보고서를 보내지만,
이 스킬은 **숫자가 움직였는지**를 확인한다. 측정 없는 최적화는 주장일 뿐이다.

## 1. 기준선 — 고치기 전에 찍어라

변경 전 상태를 기록하지 않으면 효과를 영원히 증명할 수 없다:

- Google Search Console: 최근 28일 노출·클릭·평균 순위 (페이지 그룹별)
- 네이버 서치어드바이저: 콘텐츠 노출/클릭, 검색어 Top 목록
- AI 인용: 대상 질문 5~10개를 Perplexity·ChatGPT·네이버 AI 브리핑에 실제로 던져
  출처 인용 여부를 O/X로 기록
- 색인 수: `site:도메인` 결과 수 + GSC 색인 페이지 수 (Bing도 `site:`로 확인)
- **AI 크롤러 방문 수**: 서버 로그에서 GPTBot·PerplexityBot·ClaudeBot 등의 방문 추이.
  크롤링이 와야 인용이 온다 — 인용보다 먼저 움직이는 선행 지표다

```bash
# 접근 로그에서 AI 크롤러 방문 집계 (선행 지표)
AI_BOTS='GPTBot|OAI-SearchBot|ChatGPT-User|ClaudeBot|Claude-SearchBot|Claude-User|PerplexityBot|Perplexity-User|CCBot|Google-Agent'
grep -ciE "$AI_BOTS" access.log
# 응답 코드 분포 — 403·429가 보이면 CDN·WAF가 막고 있다 (combined 로그 형식의 9번째 필드)
grep -iE "$AI_BOTS" access.log | awk '{print $9}' | sort | uniq -c
# 로그 접근이 없으면: Cloudflare/Vercel 등 호스팅 대시보드의 봇 트래픽 분류로 대체
```

## 2. 재측정 일정 — 작업의 일부다

- 검색 반영에는 시차가 있다: **변경 후 14일 뒤 재측정**을 기본으로,
  집계 지연을 감안해 최근 2~3일은 빼고 비교하라
- 재측정을 "기억"에 맡기지 마라 — 일정에 박거나, 에이전트에게 리마인드를 걸어라.
  이 스킬로 작업했다면 보고에 재측정 날짜를 명시하는 것이 완료 조건이다

## 3. 낡은 데이터 함정

> **낡은 데이터는 모든 하한선을 통과한다.**

지표가 "0이 아님"만 확인하는 감시는 며칠 전 값이 계속 내려와도 통과시킨다.
측정 파이프라인을 만들 때는 값이 아니라 **값의 날짜**를 감시하라 —
"마지막 갱신이 N일 이상 낡으면 그 지표는 표시하지 않는다"가 안전한 기본값이다.

## 4. 읽는 법

- **노출 먼저, 클릭은 나중**: 구조 개선의 첫 신호는 노출 증가다. 클릭(CTR)은
  제목·설명 개선이 따라가야 움직인다. 노출만 늘고 CTR이 낮으면 다음 작업은 메타다
- **주말 하락은 정상**: 평일성 주제(비즈니스·금융)는 주말에 노출이 꺼진다.
  오히려 그 패턴이 실수요의 증거다
- **검색어 목록이 로드맵이다**: 서치어드바이저·GSC의 검색어 Top은 "사람들이 실제로 치는
  질문" 목록이다. 상위 검색어 중 전용 랜딩이 없는 질문 = 다음에 만들 페이지

## 5. 보고 형식

```
[기준선] 8/1~8/28: 노출 12,400 · 클릭 180 · AI 인용 0/8 질문
[변경] 8/29: 의도 랜딩 6종 + llms.txt + FAQ LD
[재측정 예약] 9/12
[재측정 결과] 노출 31,000(+150%) · 클릭 610 · AI 인용 3/8  ← 이게 나와야 완료
```
