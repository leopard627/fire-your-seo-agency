# AEO — 답변엔진 최적화 (Google AI Overviews·AI 모드 · Bing Copilot)

검색 결과 맨 위 AI 답변 박스가 당신을 인용하게 만드는 레인. 답변엔진은 페이지를 "읽고
요약"하는 게 아니라 **답이 되는 문장을 찾아 추출**한다. 추출되기 좋은 형태가 전부다.

## 0. Bing 등록 — 잊혀진 절반

GSC만 보고 Bing을 안 하는 사이트가 대부분인데, **Copilot은 Bing 색인에서 답을 꺼내고,
ChatGPT 검색도 Bing 색인에 크게 의존한다.** Bing 미등록 = AEO·GEO 절반을 버리는 것.

- [ ] [Bing Webmaster Tools](https://www.bing.com/webmasters) 등록 — GSC에서 원클릭
      임포트 지원 (소유 확인·사이트맵까지 가져온다). 10분짜리 작업이다
- [ ] 사이트맵 제출 확인 + IndexNow 연동 (Bing은 IndexNow를 직접 소비한다)
- [ ] Bing 검색에서 `site:도메인`으로 색인 여부를 실제 확인

## 원칙: 질문 하나 = 페이지 하나

- 사람들이 검색창에 치는 질문("○○ 실적발표 언제", "○○ 배당일")마다 전용 페이지를 둔다.
  한 페이지에 열 가지 질문을 다루면 어느 질문의 답으로도 추출되지 않는다.
- URL·h1·title이 질문을 그대로 반영한다.

## 추출되는 문장의 형태

- [ ] **첫 문단에서 직답**: 질문에 대한 답을 40자 내외 한 문장으로, 페이지 최상단에.
      "결론부터: ○○의 다음 실적 발표는 2026년 11월 14일(장 마감 후)입니다."
- [ ] **문장이 독립적으로 사실을 말하게**: "위에서 언급한 그 수치"처럼 맥락 의존 문장은
      추출되면 무의미해진다. 각 문단이 주어·수치·기준일을 자체 보유해야 한다.
- [ ] **기준·날짜 명시**: "PER 13.8배(2026-08-26, 최근 4개 분기 기준)" — 기준 없는 숫자는
      답변엔진이 신뢰 판정에서 감점한다.
- [ ] 표를 써라: 엔진은 표를 구조화된 사실로 안정적으로 파싱한다.

## FAQ 블록

- [ ] 페이지 하단에 실제 검색 질문 3~5개로 FAQ 섹션 구성
- [ ] FAQPage JSON-LD를 붙이되 **가시 텍스트와 글자까지 동일하게** — 다르면 스팸 판정
- [ ] 답변은 데이터로 확정되는 것만. 예측·권유형 문답은 넣지 않는다 (규제 업종은 특히)
- ℹ️ **기대치 관리**: 구글은 2023년 8월부터 FAQ 리치 결과(검색 결과의 접이식 문답 UI)를
  정부·의료 등 권위 사이트로 제한했고 HowTo 리치 결과는 폐지했다. 그래도 FAQPage LD를
  붙이는 이유는 리치 결과가 아니라 **엔진의 콘텐츠 이해와 답변 추출**이다 — 목적을
  혼동해 "별이 안 뜬다"고 떼지 마라

## 신뢰 신호 (E-E-A-T)

답변엔진은 "누가 말하는가"를 본다. 같은 데이터도 익명 페이지보다 실체가 확인되는
페이지가 인용된다:

- [ ] **운영 주체 공개**: About 페이지에 누가·왜 만들었는지 + Organization JSON-LD와 연결
- [ ] **저자·출처 표기**: 데이터 페이지에 "어디서 온 데이터를 어떻게 가공했는지" 명시
      (예: "전자공시 원문 기반 자체 산출, 매일 갱신")
- [ ] **연락 가능성**: 문의 수단(이메일·폼)이 있는 사이트가 유령 사이트보다 신뢰 점수가 높다
- [ ] **dateModified 정직하게**: 실제 갱신 시점을 구조화 데이터에 — 내용 변경 없이
      날짜만 올리는 조작은 감지되면 역효과다

## 검증

- 배포 후 해당 질문을 실제로 구글·빙에 검색해 AI 답변 인용 여부를 확인하고 기록한다.
- 인용이 안 되면: ① 직답 문장이 첫 화면에 있는가 ② 경쟁 페이지 대비 데이터 신선도
  ③ 페이지 신뢰(도메인 연식·구조화 데이터) 순으로 점검.
